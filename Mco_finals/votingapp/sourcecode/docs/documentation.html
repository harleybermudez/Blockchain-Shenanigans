Election management

Add candidates, review and approve wallets, start voting, and close it permanently.

Setup requires at least two candidates and one approved voter before starting. Candidate fields normalize whitespace and validate byte length. The first candidate fixes the position. A close action asks for review and permanently stops further votes.

Candidate list

Read candidate names and positions. Candidate counts are displayed only when the election is closed.

Voting

Choose one candidate, review the choice, and confirm the transaction. A recorded vote disables another vote.

The contract remains the final authority when the interface is bypassed. It checks electionOpen, authorizedVoters, hasVoted, and candidate existence before incrementing counts. contracts/CampusVoting.sol line 104

Final results

Keep tabulation hidden until the contract is closed, then display candidate counts and total votes.

The frontend checks the closed phase before displaying the table. Counts are public on the blockchain throughout the election. The interface hides live tabulation but the contract does not implement a secret ballot.

Wallet requests and transaction confirmation

The frontend first checks that MetaMask still exposes the selected wallet and configured network. It shows “Confirm in MetaMask” while requesting the signature, then “Recording. Please wait.” until transaction.wait() returns a successful receipt. Cancelled or failed requests produce an error message. A confirmed transaction triggers a fresh election read.
